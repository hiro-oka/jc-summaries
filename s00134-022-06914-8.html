🏥 聖路加ICUでの実践への示唆

聖路加ICUでの実践

当院・JIPADでの使い方に落とし込む

  • スコアの用途を宣言してから使う。本稿の骨子は「予後予測（個人）」「群のリスク調整比較（ベンチマーキング）」「治療反応のモニタリング」が別目的だという点にある。カンファで APACHE II や SOFA を口にするとき、どの目的で言っているかを先に言う。
  • 個々の患者の治療方針決定にスコアを使わない。著者は、個人へのスコア適用がスコア開発時のバイアスを永続させ、倒錯した行動（perverse behavior）を招きうると明記している。予測死亡率が高いことは、治療の差し控えの理由にならない。
  • SMRは同一条件でしか比べない。同一スコア・同一期間・同一定義がそろって初めて比較になる。SAPS3（2005）と APACHE IV（2006）はいずれも発表から15年以上経ち、較正の劣化は当然と著者は述べる。当院のSMRを他施設や過去年度と並べるときは、係数が同じ版かを確認する。
  • JIPADの再較正は世界標準の作法。英国 ICNARC・豪NZ ANZROD のように国別レジストリが自前のモデルを開発・更新・再較正してきた系譜に、JIPADのJROD開発とサブグループ別再較正は正しく乗っている。本稿はその作業を「よりよいベンチマーキングのために必要」と評価している。
  • 専門集団への適用には留保をつける。移植・神経集中治療・COVID-19 のように、一般集団で開発されたスコアが不正確になる集団がある。当院の術後心臓外科や脳卒中ユニットのデータを一般スコアで評価する際、この限界を議事録に残す。
  • 国際比較の入口は LOGIC と GOSSIS。JIPADが関わる国際ベンチマーキングの議論はこの2つを軸に進む。用語として押さえておく。
  • AI予測モデルの院内導入を検討するときの前提：予測能が上がることと、使い方の教訓が変わることは別。40年かけて学んだ「個人への適用の危うさ」は機械学習モデルにもそのまま当てはまる、というのが本稿の最終メッセージ。

🧭 この論文の位置づけ（Known / Unknown / What's new）

補足

リサーチ・イン・コンテキスト

  • Known（既に分かっていたこと）：1980年代初頭の APACHE 以来、重症度スコアはICUの転帰予測とリスク調整の基盤であり、SAPS3・APACHE IV・MPM0-III といった第3世代への更新も済んでいる。SOFA は敗血症の定義（Sepsis-3）に組み込まれ、日常語になっている。
  • Unknown（分かっていなかったこと）：国別レジストリが独自モデルを持つようになった一方で、国境をまたぐICU比較を成立させる単一のスコアは存在しない。既存スコアの較正劣化にどう対処するか、また特定集団や新興感染症にスコアをどう当てるかも決着していない。
  • What's new（本稿の意義）：原著研究ではなく、ICM誌の Lasting Legacy シリーズによる40年の総括。新データは提示せず、スコアが残した「遺産」はスコアそのものではなく運用上の教訓であると論じる。とくに「個人ではなく群に使う」という教訓を、機械学習・AIの時代に持ち越すべき資産として提示した点が主眼。LOGIC・GOSSIS という世界共通スコアの試みを、その延長線上に位置づけている。

📌 全体要約

要旨

ひとことで 40年を経てもICUスコアはICU評価の中核だが、その最大の遺産は「スコアは個人ではなく患者群に使う」という運用上の教訓であり、AIの時代にこそこの教訓を持ち越すべきだ、という総括。

  • 成立の動機：1970〜80年代、集中治療のコスト増と多臓器不全患者の転帰不良を背景に、集中治療医と医療管理者が「重症度を簡潔に表現し、リスク調整済み転帰を測れる指標」を求めた。
  • APACHE が画期：1980年代初頭、前病態（年齢・併存症）・診断・早期の生理学的異常（臓器不全、検査・生理学的異常）という領域を重症度の数値表現に翻訳した。加えて、個々の患者ごとの死亡リスク推定値を与えた。
  • 続いた開発：米国で MPM（Mortality Prediction Model）、欧州で SAPS（Simplified Acute Physiology Score）。
  • 第3世代への更新：技術進歩・新しい治療とプロトコル・ケースミックスの変化（高齢化、併存症の増加、免疫不全患者の増加）により更新が必要になり、SAPS3（2005年）・APACHE IV（2006年）・MPM0-III（2007年）が発表された。
  • 計算タイミングの相違：SAPS3 と MPM0-III は ICU入室後最初の1時間のデータ、APACHE IV は最初の24時間の「最悪」値を使う。前者は蘇生前の早期重症度を反映しうる一方、後者はデータ収集時間が長く欠測が少ない。
  • 動的スコア：最も一般的なのは SOFA。臓器不全の程度の定義、とくに敗血症患者のリスク層別化、治療反応のモニタリングのために開発された。
  • ベンチマーキング：英国・イタリア・豪州・NZ など多くの国別レジストリが独自の死亡予測モデルを開発・更新・再較正し、現行の予後スコアより優れた地域ベンチマーキングを実現した。それでも国際比較は依然として困難。
  • 価値のステークホルダー：本文は臨床研究者・ICU管理者およびスタッフ・医療管理者および支払者の3者を挙げ、Fig. 1 はさらに政策立案者と政府・社会を加えた5者を図示する。
  • 中心的な教訓：スコアや予測を個人に適用することは、開発に内在するバイアスを永続させ、倒錯した行動を招きうる。重症度スコアは当初こそ個々の患者への適用のために開発されたが、臨床医はすぐに、患者群のリスク調整済み転帰を比較・解釈する用途に最も適していると学んだ。
  • 較正の劣化：SAPS3 と APACHE IV はいずれも発表から15年以上経っており、時間とともに較正が悪化するのは当然。スコアは固定された参照点を与えるが、そこから導かれる死亡推定値は反復的な更新を要する。
  • 国際化の試み：LOGIC（Linking of Global Intensive Care）と GOSSIS（The Global Open Source Severity of Illness Score）。ただし単一のICUスコアが必要要件をすべて満たすには、まだ長い道のりがある。

1. まず前提 — ICU重症度スコアの基礎（初学者向け）🧩

要旨

5分で背景を掴む 以下は論文本文の記述ではない。本稿を読むための一般的な背景知識である。本稿は解説記事のため、用語の定義をほとんど省いている。論文本文の主張と混ざらないよう、この節に分離して置く。

重症度スコアとは何か：入室時の年齢・併存症・診断・生理学的異常（血圧、体温、酸素化、意識、検査値など）を点数化し、合計点から「この患者集団に期待される死亡率」を計算する仕組み。点数そのもの（severity score）と、そこから確率を出す方程式（prediction model）は別物で、後者が時代とともにずれていく。

SMR（standardized mortality ratio）：実測死亡数 ÷ 予測死亡数。1より小さければ「予測より良い成績」と読む。ICU間の比較（ベンチマーキング）はほぼこの指標で行われる。予測死亡数はスコアの方程式が出すので、方程式がずれていればSMRもずれる。

識別能と較正（discrimination / calibration）：識別能は「死んだ人と生きた人を並べ替えられるか」（AUROC で表す）。較正は「予測10%の集団が本当に10%死ぬか」。識別能は保たれたまま較正だけが崩れることがよく起き、これが「較正ドリフト」と呼ばれる現象。ベンチマーキングで問題になるのは主に較正のほう。

静的スコアと動的スコア：APACHE・SAPS・MPM は入室時点の1回きり（静的）。SOFA は毎日つけて推移を見る（動的）。測っているものが違うので、目的も違う。

本稿で登場する主要スコアの正式名称：APACHE = Acute Physiology and Chronic Health Evaluation／MPM = Mortality Prediction Model／SAPS = Simplified Acute Physiology Score／SOFA = Sequential Organ Failure Assessment。

2. 背景と目的 — なぜ「重症度」を数値化する必要があったか 🏥

ICUは人的資源と技術が集中する環境であり、高度なモニタリングと生命維持を適時かつ賢明に用いることが、生命を脅かす状態を回復させる／回避するうえで決定的である。著者はこの前提を置いたうえで、ICUは成立当初から、医療のステークホルダーに対して自らの有効性を示す必要に直面してきたと述べる。

1970〜80年代、集中治療のコスト増加が多臓器不全患者の転帰不良と結びつき、集中治療医と医療管理者は「重症度（severity of illness）を簡潔に表現でき、それによってリスク調整済み転帰の測定を可能にする指標」を探すことを迫られた。これがスコアリングシステムの出発点である。

本稿の目的は、この40年を振り返り、スコアが何を残したのかを、AI・機械学習が予測能力を持ち込みつつある現在の文脈で問い直すことにある。

4. スコアの世代交代 — APACHE から第3世代へ 📜

1980年代初頭、APACHE システムはICU転帰予測の歴史における画期（milestone）であった。このスコアリングシステムがしたことは2つある。

  1. 前病態（年齢・併存症）／診断／早期の生理学的異常（臓器不全、検査・生理学的異常）という各領域を、重症度の数値表現へ翻訳した。
  2. スコアの絶対値に加えて、個々の患者について死亡リスクの推定値を提供した。

APACHE の後を追って、米国では MPM、欧州では SAPS が開発された。その後、技術が改善し、新しい治療とケアのプロトコルが適用され、ICUのケースミックスが変化した（より高齢に、より併存症が多く、より免疫不全患者が多くなった）ため、スコアは妥当な転帰予測因子であり続けるために更新を要した。

5. 動的スコアと、SOFA の位置 🔄

最後に、動的スコア（dynamic scores）がICUで適用されうる、と著者は続ける。最も一般的なのが SOFA であり、①臓器不全の程度を定義するため、②とくに敗血症患者でリスクを層別化するため、③治療への反応をモニタリングするため、に開発された。

続く1文は本稿でもっとも解釈が割れる箇所である。原文は「スコアリングシステムは、個々のリスク評価には有用であるものの、死亡予測とICUパフォーマンスのモニタリングには同程度には適用できない。ICUではより一般的な死亡スコアを補完するためにしばしば使われる」という趣旨。

「They are often used to complement more general mortality scores」＝「より一般的な死亡スコアを補完する側」である以上、この文の主語は直前の段落が論じてきた動的スコア（SOFA）を指すと読むのが素直である。SOFA は毎日の臓器不全を測る道具であって、入室時点の死亡予測やSMRの算出には向かない、という限定的な主張になる。

⚠ 注意

引用するときに事故が起きやすい一文 この文を主語を広げて「スコアリングシステム一般は個人のリスク評価には有用だが死亡予測とICU評価には使えない」と読むと、本稿全体の主張（スコアは個人ではなく群に使う）と正反対の意味になってしまう。原文は動的スコアの段落の末尾に置かれており、補完される側として「より一般的な死亡スコア」を挙げている。当院の資料で引くときは、SOFA についての記述として引くのが安全。

6. ベンチマーキング — 国内レジストリの再較正と、国際比較の壁 🌍

SAPS3 は当初 APACHE に対して優位性を示した、と著者は述べる。ただしその根拠として挙げられているのは予測性能の実測ではなく、異なる地理的地域で開発され、地域特異的な方程式（region-specific equations、supplementary table 1）を持っていたという設計上の性質である。

その理由として著者は、地理経済的（geo-economic）側面が、ケースミックス・資源の利用可能性・組織構造、ひいては転帰に、実質的な役割を果たすことを挙げる。同じ点数の患者でも、置かれた医療システムが違えば死亡率が違う、ということである。

この認識から、多くの国別ICUレジストリが自前の死亡予測モデルを持つ道に進んだ。本文が名指しするのは英国・イタリア・オーストラリア・ニュージーランドで、いずれも既存の重症度スコアを活用しつつ（leveraging previous illness severity scores）、独自モデルを開発・更新・再較正してきた。引用文献では英国 ICNARC モデル（引用文献4）と豪NZ の ANZROD モデル（引用文献5）が挙がっている。

これらは現行の予後スコアと比べて地域のベンチマーキングを改善した。しかし著者は、国際比較は依然として困難であると結ぶ。国ごとに別々のモデルを持てば国内比較は精密になるが、その代償として国境をまたいだ比較ができなくなる、という構造的なトレードオフがここにある。

本文の段落が言及するのは、このうち臨床研究者（疾患重症度の評価、介入の成否の解釈）、ICU管理者とスタッフ（パフォーマンスのベンチマーク、外れ値の同定、質改善への関与）、医療管理者と支払者（集中治療のパフォーマンス評価、資源配分の計画、成果連動型インセンティブの設計）の3者のみである。政策立案者・政府と社会の2者は図にしか現れない。

図だけに現れるこの2者は、当院の文脈ではむしろ重い。「社会」の欄にあるリスク調整済み転帰の透明性と臨床医と患者家族とのコミュニケーションは、スコアが院内の管理指標にとどまらず、家族への説明や公開データの土台にもなることを示している。「政策立案者と政府」の欄にある危機への対応（response to crisis）は、パンデミック期に各国レジストリが果たした役割そのものである。

8. 学ばれた教訓 — 個人への適用の危うさ ⚠️

著者は本稿の核心をここに置く。ICUスコアリングシステムが我々に与えた遺産は、スコアそのものを超えたところにある。洗練されたデータサイエンス手法・機械学習・人工知能が、より高い予測能力とアルゴリズムを医療にもたらしつつある今こそ、時間をかけて学ばれたこれらの教訓を思い出すことが重要である。

その教訓は2文で述べられる。

  1. スコアや予測を個人に適用することは、そのスコアの開発に内在するバイアスを永続させ、倒錯した行動（perverse behavior）を引き起こしうる。
  2. 重症度スコアは当初、個々の患者への適用のために開発されたが、臨床医はすぐに、患者「群」のリスク調整済み転帰を比較・解釈するのに最も適していると学んだ。

APACHE が「個々の患者の死亡リスク推定値を提供した」ことを本稿は画期として評価している。その同じ機能が、40年後には最も注意すべき機能として名指しされる。発明の価値と運用の教訓が逆向きになったというのが、この総括の構造である。

9. 応用の広がり — スコアが生んだ派生物 🌱

重症度スコアの応用は時とともに拡張した。本文が挙げるのは次の4系統。

  • 敗血症の定義への組み込み：SOFA スコアは敗血症の定義に適用された（引用文献8＝Sepsis-3、Singer ら、JAMA 2016）。その「派生物」である Quick-SOFA は、敗血症リスク患者を同定するスクリーニングツールとして提案された。
  • ICU効率の指標：重症度スコアは資源利用の指標と組み合わされ、Rapoport-Teres プロットを用いて、頑健かつ再現性のあるICU効率の指標を提供している。
  • 在院日数・再入室の予測：重症度スコアリングシステムの開発・検証に用いられる手法が、在院日数の予測モデル（引用文献9＝Straney ら、豪NZのリスク調整済み在院日数）とICU再入室の予測モデル（引用文献10＝Badawi & Breslow）を生んだ。
  • ICU内合併症の予測：同じ手法が、褥瘡（pressure injuries）などICU内合併症の発生を予測するモデルにつながった（引用文献11＝Ranzani ら）。

つまり「重症度を数値化する方法論」自体が資産となり、死亡以外のアウトカムへ横展開された、というのがこの節の趣旨である。

10. 較正の劣化（ドリフト）と、特定集団での不正確さ 📉

本稿でJIPADの実務に最も直結するのがこの節である。

SAPS3 と APACHE IV はいずれも15年以上前に発表されており、時間とともに較正が悪化するのは当然である（it is natural that their calibration would worsen over time）。著者はこれを不具合ではなく必然として書いている。そのうえで、スコアは固定された参照点（a fixed point of reference）を提供するが、そこから導かれる死亡推定値は反復的な更新（iterative updating）を要すると述べる。

この一文の含意は実務的である。スコアの点数体系そのものは基準として残しつつ、点数から確率へ変換する部分だけを定期的に引き直す、という分業になる。

⚠ 注意

SMRの絶対値を独り歩きさせない 較正が劣化した方程式で計算された予測死亡数は、それだけで SMR を系統的に上下させる。SMR が 0.8 だった／1.2 だったという数字は、モデルの版と較正時期を添えなければ意味を持たない。当院の経営資料や学会発表で SMR を出すときは、どのモデルの何年版かを必ず併記する。

さらに、一般集団で開発されたスコアは、移植患者・神経集中治療患者、より最近では COVID-19 といった特定の集団に適用すると不正確でありうる（引用文献12＝Kurtz ら、ブラジルのICUに入室した COVID-19 患者30,571例における SAPS-3 の院内死亡予測性能、ICM 2021）。

COVID-19 パンデミックは、疾病負荷と転帰の世界的比較の必要性も浮き彫りにした。ただし著者はここで留保を置く。転帰が地域の医療システムへの負荷（strain）に強く影響される新しい病態に対してスコアを開発することには、潜在的なリスクもある。つまり、パンデミック下のデータで作ったモデルは「病気の重さ」ではなく「その地域の医療が逼迫していた度合い」を学習してしまう危険がある、という指摘である。

参考：一般的な背景知識（本稿の記述ではない）

較正ドリフトへの対処として、切片だけを引き直す再較正（recalibration in the large）、切片と傾きを引き直す方法（logistic recalibration）、モデル全体を作り直す方法（model revision）が知られる。またサブグループごとに較正が異なる場合はサブグループ別の再較正が要る。これらの手法は本稿には一切書かれていないが、JIPADのJROD開発やサブグループ別再較正の議論に直結するため、区別したうえで併記しておく。

11. 協働、レジストリ、そして世界共通のスコアへ 🤝

著者は「重要なことに（Importantly）」と前置きして、重症度スコアの開発は、複数の情報源・施設・管轄からデータを集める用意のある個人間の協働なしには不可能だったと述べる。技術ではなく人の協働が前提条件だった、という指摘である。

ブラジル・アルゼンチン・ウルグアイ、およびアフリカとアジアの地域を含む多くの国が、現在では確立されたICUレジストリを持ち、国内および国家間でのICU比較を可能にしている。これにより医療システム間の違いと共通点、情報へのアクセス、そして限界をよりよく理解できるようになった（引用文献13＝LOGIC、引用文献14＝低・中所得国における予後スコアの性能を検討した系統的レビュー）。

著者はこれらに要件を課す。新しい国際的スコアリングシステムは、よりアクセスしやすく（more accessible）、異なる医療システムを代表する不均質なケースミックス（heterogeneous case-mix）を持つべきである。この種の協働は世界規模でICU診療のベンチマーキングを改善するはずだ、としつつ、単一のICUスコアリングシステムが必要な要件をすべて満たすまでには、まだ長い道のりがあると締める（要件の詳細は supplementary Fig. 1 にあるとされるが、本PDFには含まれない）。

12. 原文の Take-home message（本文最終節の全訳）📝

40年以上を経て、ICUスコアリングシステムはICUパフォーマンス評価の中核（mainstem）であり続けている。しかしその役割は、個人や単一ICUの評価を超え、より幅広い医療ステークホルダーにとって重要なものになってきた。スコアの限界と強みの両方についての我々の経験を、技術・ビッグデータ・機械学習手法の興隆と組み合わせることで、我々は近いうちに大きな変化と改善を目にするかもしれない。それは最終的に、より広範で正確な実装と、ICU間の国際比較を可能にするだろう。

最後の一文は、旧版の本ノートで落ちていた部分である。著者は悲観で終わらせておらず、限界の経験と新技術を組み合わせるという条件付きの楽観を置いている。

🔬 批判的吟味（JCでの論点）

  1. 典拠として使える範囲が狭い。解説記事であり系統的レビューではない。文献選択の方法は記されず、引用は15件。「APACHE II はいつか」「SAPS3 のAUROCはいくつか」といった具体を本稿から引くことはできない。定量データがゼロである点は、資料作成時に何度でも確認すべき制約。
  2. 利益相反の位置。責任著者はベンチマーキング用クラウドシステム（Epimed Solutions）の株主である。本稿は「レジストリとベンチマーキングの価値」を主張する稿なので、この開示は結論の重みづけに関わる。ただし本稿の主張は特定製品を推すものではなく、開示も明記されている。
  3. 「個人に使うな」と「APACHE が個人の死亡リスクを提供した」の緊張。本稿は APACHE の功績として個人リスク推定を挙げつつ、教訓としては個人適用を戒める。では個人の死亡リスク推定は何のために提供されたのかという問いに本稿は答えていない。JCで議論する価値がある。
  4. 国別モデルと国際比較のトレードオフに解がない。国別レジストリが独自に再較正するほど国内ベンチマーキングは精密になるが、国際比較は遠のく。本稿はこの構造を指摘するが、LOGIC・GOSSIS が具体的にどう解くのかは示していない（要件は supplementary Fig. 1 に外出しされている）。
  5. 較正劣化への対処法が書かれていない。「反復的な更新を要する」で止まっており、誰が・どの頻度で・どの手法で再較正するのかには踏み込まない。JIPADの実務ではここが最も知りたい部分であり、本稿だけでは足りない。
  6. AIへの警告が抽象にとどまる。「個人適用のバイアス」という教訓を機械学習に持ち越せ、という主張は正しいが、機械学習モデル特有の問題（学習データのシフト、ブラックボックス性、施設固有の交絡の学習）には触れていない。パンデミック下のstrainを学習するリスクを指摘した一文が、唯一その方向を向いている。
  7. 「社会」の視点が図にしかない。リスク調整済み転帰の透明性と家族とのコミュニケーションは、本文では一度も論じられない。図が本文より進んでいる状態であり、この非対称は本稿の弱点でもあり、次の論考への入口でもある。

✅ Take home message

TAKE HOME

結論 重症度スコアの40年が残した最大の遺産はスコアそのものではなく、「個人ではなく患者群に使う」という運用上の教訓である。SAPS3 と APACHE IV は発表から15年以上経ち、較正の劣化は必然。スコアは固定された参照点を与えるが、そこから出る死亡推定値は反復的な更新を要する。国別レジストリの再較正はこの必然への正しい応答であり、JIPADの作業はその系譜にある。国際比較のための LOGIC・GOSSIS は進行中だが、単一のスコアが要件をすべて満たすには「まだ長い道のり」がある。そして、AIと機械学習がより高い予測能をもたらす今こそ、この教訓を持ち越すべきである。
